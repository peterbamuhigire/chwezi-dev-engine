# Software delivery specialists

Select contributors for the affected engineering decisions. The product designer, analyst, database and AppSec assignments extend the existing specialist roles. A PHP tester can own a language-specific regression within QA.

| Specialist | When to involve them | What they should return |
|---|---|---|
| Product manager (PM) | Discovery, before choosing what to build | PRD with user stories, functional requirements and acceptance criteria. Rank the backlog by user impact and business value. Define adoption, retention or conversion targets with a baseline, denominator and observation window. |
| Business analyst / systems analyst | Scoping workflows, exceptions and quality requirements | Functional and non-functional specifications with state transitions, applicable rules and measurable limits. Diagram current and proposed processes (BPMN where useful) and data flows. Trace each business rule to a test case. |
| UX/UI product designer | After requirements are understood and before client implementation | Wireframes and a clickable prototype for representative user journeys. Specify components, type, spacing, responsive breakpoints and interaction states. Return usability findings and accessibility checks against the agreed WCAG criteria, with retest evidence. |
| Software / solutions architect | Before major builds, integrations or refactors | C4 context and container views, ADRs explaining alternatives and trade-offs, and versioned API contracts such as OpenAPI. Specify failure behaviour and verify that producers and consumers agree. |
| Database administrator / data engineer | Before persistence, reporting or high-volume query changes | ERD with keys, constraints, indexing and justified denormalisation. Supply migration and test-data seeding scripts, backup and retention plans, partitioning or replication decisions, and measured query plans. Rehearse restore and any promised zero-downtime migration. |
| Backend engineer | When business rules and service interfaces are ready to implement | Version-controlled APIs and business logic, authentication and authorisation including RBAC and token handling where applicable, input validation, and unit and integration tests for ordinary, denied and failed requests. |
| Frontend / mobile engineer | Once the interaction design and API contract support client work | Responsive web or native screens, state management, caching, offline and optimistic-update recovery where relevant. Exercise a mock and the real API. Report bundle size, applicable web or mobile performance measures and observed browser or device compatibility. |
| Quality assurance / SDET engineer | From requirements review through staging and release assessment | A risk-based test plan and cases for success, edges and regressions. Supply repeatable end-to-end and load suites with recorded environments and results. Return reproducible defects, severity, outstanding risks and a go/no-go recommendation to the release owner. |
| DevOps / site reliability engineer (SRE) | At environment setup and throughout delivery and operations | CI/CD build, test and rollout pipelines, versioned infrastructure and container configuration, and rollback evidence. Provide logs, APM metrics, alert thresholds, incident and recovery runbooks. Record observed downtime and recovery from rehearsal. |
| Application security / DevSecOps specialist | At design review, in CI and before high-risk releases | A threat model with trust boundaries and mitigations, plus appropriate static analysis, dependency, secret and approved dynamic-scan results. Verify access controls, encryption, audit logs and privacy requirements. Reference any authorised penetration-test report, record remediation and retest findings, and identify outstanding independent assessment. |

For an offline submission, the designer specifies the pending state, the architect records the retry contract, the client handles reconnection and the backend prevents duplicate acceptance. QA verifies recovery against the integrated build.
