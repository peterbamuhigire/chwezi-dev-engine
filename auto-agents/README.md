# Unattended coding driver

This directory contains a sequential driver for Codex and Claude. Prepare and commit a bounded plan before starting. A fresh agent session receives the plan path and repository rules; it implements and commits one slice. The driver verifies committed work independently before it can publish. Existing `scripts/autorun` implementations remain separate; do not run both against the same project or shared test environment.

## Configure and run

1. Edit `auto-agents/config.json`. Set `runner` to `codex` or `claude`; set `plan` to a committed repository-relative handoff. Populate `verify` with one or more command argument arrays, for example `[["python", "-m", "unittest", "discover", "-s", "tests"]]`. Choose checks appropriate to the actual plan and safe test environment. The empty default deliberately prevents execution.
2. Write and commit the plan, including scope, explicit authority, ordered slices, dependencies, acceptance commands, known restrictions and a concise handoff. The first line `STATUS: DONE` stops a finished run; `STATUS: BLOCKED - reason` records a blocker. Ensure the plan and driver are committed before a fresh worktree is created.
3. Run `python auto-agents/driver.py run`. Inspect with `python auto-agents/driver.py status`. Request a stop after the current session with `python auto-agents/driver.py stop`; remove the STOP file named by the command only after inspecting the state and before a deliberate restart.

`publish` is false by default. Set it true and set `remote` and `target_branch` when unattended pushing is authorised. Publication uses a regular non-force push after the verification commands succeed. Rejection blocks the run; there is no automatic rebase, merge, retry or push around a failed gate. Validate protected-branch requirements separately. Agent commits stay on `auto-agents/<runner>` in a separate worktree under the repository's Git common directory. The operator's checkout is not used for execution. Dirty, timed-out, failed, non-progressing or history-rewriting agent sessions block with logs preserved. When an independent verification command fails, the driver records the unverified commit and feeds the failure to a fresh agent session for repair; it blocks after the configured `max_gate_failures` (default three). The pending record also prevents a completion marker from bypassing verification after restart. An interrupted push may require inspection. The operator must inspect and recover before restarting.

Session count, per-session timeout, overall hours, runner, plan, checks and publish target are settings, not policy hardcoded to one product. The driver does not override the CLI's configured permissions, model or sandbox and does not override hooks. `runner_args` supplies optional CLI arguments when explicitly configured. By default `login_mode` is `plan`: the agent process does not inherit OPENAI_API_KEY, ANTHROPIC_API_KEY or ANTHROPIC_AUTH_TOKEN. Set `login_mode` to `inherit` only when API-key billing is intended. Other credentials are not removed; login and billing mode must still be verified by the operator. Configure runtime permissions separately before use. A worktree is not a security sandbox: an agent can access resources granted by its actual host permissions, and prompt restrictions are not enforcement. Use isolated non-production environments and test credentials, and independently restrict network, file and publication access as appropriate. The driver does not validate the semantic completeness of tests, detect every secret, measure token costs, or enforce process-tree termination. Logs can contain sensitive output; control access and retention. A failed or unavailable check is not a pass.

There is one repository-wide lock, shared by both runners. After a crash the lock is intentionally not stolen automatically; confirm no process is running before removing it. Worktree state is preserved. For concurrent repositories, isolate test databases and other shared services independently. No host resource preflight is performed. The time limit is checked between operations and applied as the subprocess timeout, but descendant processes may outlive their parent. A machine shutdown, sleep or network outage can interrupt a run.

Run the driver tests using `python -m unittest discover -s auto-agents/tests`. Tests use fake agents and disposable local Git repositories, never real external services. Real unattended model runs and production deployments require separate evidence.

Rate-limit retries use bounded exponential backoff with configurable retry count and delays. They run only after a failed process reports recognised limit text and leaves Git state unchanged. Text matching is heuristic and cannot establish that no external side effect occurred; disable retries with `max_rate_retries: 0` if replay is unsafe. Authentication and other errors block. There is no automatic merging, conflict resolution or clean-up of a dirty agent worktree.
